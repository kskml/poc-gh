The six pillars of token discipline

Adopt all six and you land near the 37–44% total reduction. Adopt the first three and you capture 25–30%.

01 · Context discipline

Send only what matters. 10–14% contribution. Use the escalation ladder: #selection → #file:Lx-Ly → #file → #codebase.

02 · Intelligent model routing

Match capability to task. 10–14% contribution. Plan with the big model, build with the small one.

03 · Instruction engineering

Pay once for what you'd otherwise pay every turn. 7–10% contribution. Three layers; cache the stable prefix.

04 · Reasoning depth control

Don't pay for thinking the task doesn't need. 5–8% contribution. Default to Low/Medium.

05 · Agent & tool governance

Enable, don't accumulate. 3–5% contribution. Per-workspace MCP scoping.

06 · Session lifecycle

Reset, don't compound. 5–8% contribution. One task = one session.

The three token types

Token cost is not one number. Confusing them is the most common budgeting mistake.

Input

Standard rate

Billed every turn — files, prompt, history, tool schemas, system prompt. Lever: scope · compress · cache.

Cached

~10% of input

Byte-identical prefix reused across calls earns a ~90% discount. Lever: keep the prefix stable.

Output

4–8× input

Visible reply + invisible reasoning trace. The most expensive lane. Lever: constrain · right-size.

The three token types

Input · standard rate

Every layer above except reasoning. Billed on every turn. Shrinking your own message saves almost nothing — leverage is in the other layers.

Cached · ~10% of input

Byte-identical prefix reused across calls. The 90% discount is real but fragile — any change to the front invalidates from that point forward.

Output · 4–8× input

Visible reply + invisible reasoning trace. Often dwarfs the visible output. The most overlooked cost lane.

Language tax visualizer

Tokenizers are not language-neutral. English is almost always cheapest. Non-English prompts can cost 2–3× more tokens for the same content.

Tokens for the same sentence across languages

English baseline. Bars scale relative to English token count.

Rule of thumb: tokens per 1000 words

LanguageTokens / 1K wordsvs EnglishNotes

Takeaways

  • For reusable system prompts, write in English even if user-facing output is in another language. The model translates internally — you save 30–50% on instruction tokens.
  • Tokenizer efficiency varies by provider: Gemini and Qwen are most efficient for non-English; Anthropic and Kimi are most expensive (Komatsuzaki heatmap).
  • For prompts that will be reused many times, the savings compound — every call saves the delta.

Compression rules (what gets removed at each level)

L0 · Verbose

Original prompt, no changes. Polite hedging, preamble, full sentences.

L1 · Lite

Drop "Hey", "could you please", "I think", "I'd love to", "if possible". Keep prose structure.

L2 · Full Caveman

Drop politeness + hedge + preamble. Convert to bullet imperatives. "Refactor function. Fix auth. Make efficient."

L3 · Ultra

Full caveman + abbreviate common verbs ("identify" → "find", "implement" → "add", "suggest" → "list"). Risk: ambiguity.

How the math works

Cost units are normalized so Sonnet = 1.0. Relative ratios: Haiku = 0.15×, Sonnet = 1.0×, Opus = 5.0× (based on Anthropic API pricing $1/$5, $3/$15, $5/$25 per 1M tokens).

A turn mixes input + output. We assume 10K input tokens + 1K output tokens per turn. Cache hit rate is fixed at 50% for the comparison.
